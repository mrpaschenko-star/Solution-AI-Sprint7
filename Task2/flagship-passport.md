# Паспорт №1 — приоритизация ручного финмониторинга

## 0. Канвас

| Поле | Решение |
|---|---|
| Ценность | Ускорить доказательный разбор и раньше показывать важные кейсы при фиксированном ресурсе; финансовый эффект проверяется в Task4 |
| Выполнимость | Локальный CPU ranker, existing rules/case management, без включения в платёжный critical path |
| Данные | История есть, но нет пригодной «схема/не схема» разметки; есть selection bias и задержанные исходы |
| Риск | Пропуск, очередь без срока, необоснованное вмешательство; модель не снимает обязательные процедуры |
| Вывод | Берём с условием программы разметки и безопасного пилота; supervised classifier пока не строим |

## 1. Триаж

**Гибрид**. [Общий триаж](../Task1/initiatives.md), [вход → выход, действие, обучаемое звено и пробелы](../Task1/formulations.md). Здесь модель меняет только порядок ограниченного discretionary-потока.

## 2. Постановка

| Поле | Значение |
|---|---|
| Бизнес-действие | Следующий кейс сотруднику по deadline/mandatory rules и затем рекомендации ranker |
| Объект и единица | Anchor-операция с историей клиента/контрагентов; related operations в одном case, dedup не теряет source IDs |
| Момент | Микробатч 15 минут; предлагается commit→ranking p95 ≤30 минут |
| Операция | Аномалия → порядок, не бинарное решение о схеме |
| Модальность | Табличные и временные агрегаты 1/7/30 дней; raw payment text в baseline модели не используется |
| Выход модели | anomaly score/segment percentile + model/feature versions; никакой fraud probability |
| Бизнес-выход | Priority recommendation, source facts, причины воздержания и case link; сотрудник действует по РВК |
| Источник правильного ответа | Двойной экспертный ответ «нужна проверка по guide» на доступных тогда фактах; investigation outcome и confirmed finding — отдельные delayed endpoints |
| Конвейер | Supported capture → point-in-time SQL features → Isolation Forest candidate → percentile → policy merge/ageing → UI → human → versioned labels |
| Альтернативная постановка | Автоблокировка/авторазрешение требует иных данных и отдельного допуска; в этом решении не применяется |

## 3. Оценка качества

| Поле | Значение |
|---|---|
| Бизнес-метрика | Время активного разбора, доля экспертно значимых кейсов среди проверенных, time-to-review; жалобы/приостановки — guardrails |
| Положительный класс | Только `review_worthy` по утверждённому guide, не «схема». Formal confirmed outcome учитывается отдельно после созревания |
| Метрика под решение | Yield@K и lift относительно baseline при одинаковом бюджете discretionary review; bootstrap CI по клиентам. Подтверждённый recall схем сейчас не идентифицируем |
| Baseline | Текущие mandatory rules + сумма/возраст; отдельный улучшенный rules+ageing+тот же UI baseline для отделения эффекта модели от интерфейса |
| Проверочная выборка | Temporal holdout и client-group holdout; вероятностная выборка всех операций плюс priority cases, inclusion probabilities и раздельная отчётность |
| Рабочая точка | 10 000 anchor reviews/месяц как исходный бюджет. 1 000 — контроль; mandatory M первыми, discretionary K=max(0,9000−M). При M>9000 эскалация capacity, не вытеснение обязательных проверок |
| Показатели в точке | Пока неизвестны. Предложение GO: relative lift ≥20%, нижняя граница 95% CI разницы >0, mean active time ≤9 минут; интервалы и критические сегменты отдельно |
| Цена ошибок | Ложный приоритет тратит review slot и задерживает другой кейс; пропуск оставляет риск/надзорные последствия. Денежная цена отдельного finding неизвестна |
| Guardrails | Ноль пропущенных обязательных due cases из-за reorder, ноль потерь source IDs/самовольных блокировок; complaint и reversal rates не хуже baseline сверх согласованной границы; очередь не стареет скрыто |

Порог 20% — минимальный полезный uplift для проверки расходов, **не ожидаемая точность**. 9 минут — гипотеза экономии 3 минут из 12, которая сама по себе не окупает проект. [Task4](../Task4/README.md) задаёт окончательный экономический gate.

## 4. Готовность данных

| Поле | Значение |
|---|---|
| Решение | Приоритизация проверки, не отказ в платеже |
| Объект и гранулярность | Операции, клиентские окна, case links; event_time и available_at отдельно |
| Источник и владелец | Core/account history — Core owner; cases/outcomes/РВК — финмониторинг; внешние риск-сигналы — комплаенс; доступ — ИБ/DPO/Legal |
| Источник правильного ответа | Expert guide с rubric и evidence; эскалация ≠ исход ≠ подтверждение; хранить исходную метку и время её появления |
| Доступность признаков в проде | Только полученные до score time данные; outcome, будущие возвраты/закрытие счёта исключены. Поздние corrections создают новую версию |
| Разметка | Первые 2 000 операций: два независимых эксперта, арбитраж расхождений, учёт unknown. 20% арбитража — оценка, 880 экспертных часов; далее sample 1 000/месяц + priority feedback |
| Смещение отбора | Исторические 10 тыс. проверок выбраны правилами/суммой. Непроверенное — unknown. Приоритетные labels не используются для prevalence без учёта отбора |
| Репрезентативность | Страты: flagged/unflagged, сегмент, сумма, регион, tenure, канал. В стартовом 2 000 — по 1 000 flagged/unflagged; случайный отбор внутри страт и вероятности n/N |
| Объём | 20–25 млн операций/месяц, 35 тыс. flagged, 10 тыс. reviewed, ~400 escalated. Количество confirmed — единицы и задержка месяцы. 2 000 review labels не превращаются в 2 000 fraud labels |
| Качество | Дубли IDs, запаздывания, валюты, связи юрлиц, missing tenure и признаки без истории; profiling до обучения |
| Право использовать | Вопросы цели, обучения, сроков, стороннего доступа и прав субъектов в [placement](placement.md). Наличие данных в банке не доказывает допуск к новому использованию |
| Вердикт | **Разрыв с планом закрытия**: 2–4 недели data inventory/guide, 4–6 недель стартовой разметки при выделенном ресурсе; достаточность rare findings не обещается |

Ежемесячный контроль: 1 000 случайных операций из полного universe, с положительной вероятностью в каждой существенной страте. Плановая аллокация 200 flagged + 800 unflagged пересматривается по дисперсии, веса фиксируются. Первый разбор входит в 10 000 slots; второе мнение для 20% и арбитраж 20% double-reviewed — дополнительно 48 часов/месяц. Mandatory deadlines не жертвуются ради выборки: при нехватке согласовать дополнительный ресурс, иначе online эксперимент не стартует.

## 5. Карточка эксперимента

| Поле | Значение |
|---|---|
| Где теряем | В 25 тыс./месяц прироста непроверенной flagged-очереди и в ручном поиске контекста |
| Гипотеза причины | Сумма платежа плохо отражает полезность review, а сбор фактов занимает существенное время |
| Конкурирующие объяснения | Не хватает людей; mandatory доля оставляет почти нулевой K; UI важнее модели; guide не согласован; anomalous значит новый честный клиент |
| Рычаг | Признаки, UI evidence pack и ranking policy; модель сравнивается с тем же UI без ML |
| Дешёвый различающий эксперимент | Shadow ranking на 2 000 размеченных + prospective одинаково ограниченные baseline/model очереди, blinded adjudication и контроль полного потока |
| Ожидаемый эффект | Проверяем гипотезы +20% review-worthy yield, −3 мин/кейс; не прогнозируем снижение штрафов/жалоб числом |
| Стоимость проверки | До 12 недель и лимит 4,53 млн ₽ по [плану](../Task4/pilot.md); обучение CPU, программа разметки обязательна |
| Критерий остановки | Нельзя получить согласованный guide/допуск, mandatory capacity не обеспечена, нет lift после заранее заданного лимита, либо guardrail breach |
