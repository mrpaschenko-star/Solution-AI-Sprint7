# Паспорт №2 — OCR кредитных документов

## 0. Канвас

| Поле | Решение |
|---|---|
| Ценность | Меньше ручной транскрипции в 90-минутной обработке заявки; вклад OCR ещё надо измерить |
| Выполнимость | Self-hosted OCR, native PDF text bypass, sandbox файлов, human correction |
| Данные | Исходный документ даёт проверяемый эталон, но corpus и разбивка неизвестны |
| Риск | Неверные цифры/минус, пропавшая строка, заражённое вложение; нельзя автоматически менять кредитное решение |
| Вывод | Берём с условием corpus/доступа и проверки критичных цифр |

## 1. Триаж

**Гибрид**. [18 инициатив](../Task1/initiatives.md); [полная исходная постановка](../Task1/formulations.md). OCR отвечает за текст и geometry, не за подлинность документа и не за смысл финансового показателя.

## 2. Постановка

| Поле | Значение |
|---|---|
| Бизнес-действие | Оператор проверяет/исправляет текст рядом со сканом |
| Объект и единица | Страница versioned документа, document hash и page ID |
| Момент | Async после безопасной загрузки; pilot SLO p95 ≤60 с/страницу при согласованном лимите размера, предложение |
| Операция | Распознавание/извлечение текста |
| Модальность | Изображение, PDF-скан, фото; native Excel/PDF обрабатывается parser отдельно |
| Выход модели | Tokens, строки/блоки, bbox, confidence конкретного OCR engine |
| Бизнес-выход | Исправляемый OCR слой, список unreadable/low_quality страниц и provenance |
| Источник правильного ответа | Два транскрибатора по изображению + арбитраж; невидимый текст не восстанавливается по догадке |
| Конвейер | MIME/size gate → AV/sandbox → page render/orientation → native text check/OCR → completeness/geometry/schema checks → review |
| Альтернативные постановки | Полнотекстовый поиск и заполнение бизнес-полей — другие consumers; рукопись в MVP excluded до отдельной приёмки |

## 3. Оценка качества

| Поле | Значение |
|---|---|
| Бизнес-метрика | Минуты ручной транскрипции/страницу, correction load, end-to-end заявки без двойного учёта с №18 |
| Положительный класс | Не применимо к транскрипции; оцениваются символы/поле и обнаружение нечитаемого |
| Метрика под решение | CER по strata, exact match значимых числовых tokens, page omission; coverage при abstain |
| Baseline | Ручной ввод и локальный Tesseract; чистый native-text parser для born-digital |
| Проверочная выборка | 1 200 страниц ≥300 документов: 400 clean scans, 300 photos, 250 tables, 150 low-quality, 100 malformed/out-of-scope; split по документу/шаблону, не странице |
| Рабочая точка | Engine confidence threshold выбирается на dev; all numeric fields перед кредитным использованием подтверждает человек |
| Показатели в точке | Проектные gates: clean CER ≤1%, photo CER ≤3%; numeric exact ≥99,5% на accepted tokens; accepted page coverage ≥80%; 0 silent page loss. Порог не доказан |
| Цена ошибок | Пропуск/замена цифры может исказить оценку заёмщика; abstain увеличивает ручную нагрузку |
| Guardrails | Не терять страницы, сохранять hash/bbox, не снижать ручной контроль критических полей; отказ parser не приводит к пропуску документа |

## 4. Готовность данных

| Поле | Значение |
|---|---|
| Решение | Достоверная черновая транскрипция |
| Объект и гранулярность | Документ/страница/token; версии image/OCR/correction |
| Источник и владелец | Архив заявок — кредитный бизнес/документооборот, доступ ИБ/DPO |
| Источник правильного ответа | Видимое содержимое оригинала; маскированные и синтетические tests дополняют, не заменяют real holdout |
| Доступность признаков в проде | Байты файла, тип и page geometry доступны после sandbox; metadata клиента не нужна модели |
| Разметка | Двойная транскрипция, disagreement по символам/числам, арбитраж, bbox alignment |
| Смещение отбора | Нельзя брать только одобренные заявки/чистые PDF; poor photos и отказные пакеты представлены |
| Репрезентативность | Банки-источники, языки, device/photo, scan quality, таблицы и новые шаблоны |
| Объём | Число страниц кейсом не дано; нужен inventory. План 1 200 eval + 300 dev отдельно, без заявлений о достаточности всех шаблонов |
| Качество | Rotation, blur, missing pages, digital signature/text layer mismatch, рукопись |
| Право использовать | Отдельно допуск заявок для benchmark/обучения, retention, обработчик; по умолчанию локальный контур |
| Вердикт | **Разрыв с планом закрытия**: 2 недели inventory + 3–4 недели corpus/benchmark при выделенных людях |

## 5. Карточка эксперимента

| Поле | Значение |
|---|---|
| Где теряем | Ручной набор и исправления на фото/таблицах |
| Гипотеза причины | OCR с orientation/layout лучше простого OCR без preprocessing |
| Конкурирующие объяснения | Фото физически нечитаемо; неправильный render; operator UI тормозит; таблица теряет структуру после распознавания |
| Рычаг | Preprocessing/layout/model, не prompt для угадывания цифр |
| Дешёвый эксперимент | Tesseract vs PaddleOCR на одинаковых pages; ablation deskew/layout и измерение correction time |
| Ожидаемый эффект | Gate: ≥30% меньше времени именно транскрипции при качестве выше; не 30% от всех 90 минут |
| Стоимость проверки | Оценка: 1 500 страниц ×2×5 мин +20% арбитража×5 мин =275 ч; при 1 000 ₽/ч 275 тыс. ₽, ещё 120 инженерных часов×2 500=300 тыс. ₽; infra отдельно после benchmark |
| Критерий остановки | Не проходят numeric/source gates, abstain делает коррекцию не быстрее baseline, либо допуск corpus не получен |
