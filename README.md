# Solution-AI—Sprint7: от инициатив к проверяемому ИИ-сервису

Рекомендация: **ограниченный пилот приоритизации финмониторинга; промышленное внедрение пока не одобрять**. В кейсе нет надёжной разметки схем, а эскалация не равна подтверждению. Модель предлагает порядок проверки; правила внутреннего контроля и решения уполномоченных сотрудников сохраняются.

| Задание | Результат |
|---|---|
| [Task1](Task1/README.md) | Триаж всех 18 инициатив; выбор №1, №2 и №18, полные постановки |
| [Task2](Task2/README.md) | Три паспорта по шаблону, готовность данных, размещение, выбор моделей, три ADR |
| [Task3](Task3/README.md) | C4 Container/Component флагмана и Container двух документных сервисов; контракты, надёжность, безопасность |
| [Task4](Task4/README.md) | Воспроизводимый TCO на 12/24 месяца, рыночные источники, допущения, пилот и решение |
| [Task5](Task5/README.md) | Конкурирующие причины деградации на селлерах, диагностика, изменение архитектуры, rollout/rollback |

Документы — Markdown. Диаграммы — **PlantUML с локальной C4-PlantUML v2.12.0**, превью — **PNG**. [Генерация и проверки](tools/README.md). Шаблон паспорта/ADR прочитан по ссылке из источника; [источники и соответствие шаблону](sources/README.md).

Состояние пилота, метрики качества, загрузка оборудования, права на данные и экономический эффект фактически не проверены. Численные пороги приёмки и внутренние ставки — предложения с объяснением, не результаты измерений.

Кейс продолжает RetailBank, но задаёт отдельные условия: 180 тыс. клиентов МСБ и 20–25 млн операций в месяц. Из Sprint 6 сохраняются принципы ownership, изоляции аналитики и lineage; проектные MDM/Lakehouse не объявляются уже внедрёнными зависимостями пилота. В частности, срок пилота здесь — наше предложение, а не обязательные три месяца из прошлого задания.
